# 微信审核版回滚方案 V1

状态：**待负责人补全回滚目标后生效。** 本轮不执行回滚、不修改线上数据、不部署云函数。

## 回滚前提

- [待负责人填写] 微信公众平台上一稳定线上版本号、发布时间和版本说明。
- [待负责人填写] 对应源码 commit/归档和构建校验值。
- [待负责人填写] 对应云函数版本及安全环境变量摘要。
- [待负责人填写] 发布负责人、技术负责人和回滚批准人。

仓库当前没有可信的上一稳定版本记录；`HEAD` 也早于大量未提交修改，因此不能直接声明 `git checkout` 某提交即可回滚。

## 回滚触发条件

- 启动白屏、核心页面不可达或持续崩溃。
- 跨用户/跨企业数据可见、敏感信息泄露。
- 意外真实扣点、支付、批量真实生成或自动交付。
- mock/fallback 可被正式审核或交付。
- 核心任务重复创建、任务无法找回或作品错误归属。
- 隐私授权、客服或协议页面与审核声明严重不一致。

## 执行顺序

1. 暂停继续上传和提交审核，保存脱敏证据。
2. 优先关闭云端真实 Provider、真实 quota、批量和交付开关；不得依赖前端隐藏。
3. 在微信公众平台版本管理选择已确认的上一稳定版本执行平台允许的回退操作。
4. 云函数只回退到已记录并核验过的版本；额度事务和数据库不做临时手工改写。
5. 不删除任务、作品、额度记录、线索或客户数据，不执行破坏性迁移。
6. 回退后验证首页、作品、我的、客服、隐私页面以及 mock/fallback 交付阻断。
7. 记录回退时间、原因、版本、云函数摘要、验证结果和负责人。

## 分层回滚

| 层级 | 首选动作 | 禁止动作 |
| --- | --- | --- |
| 小程序前端 | 回退到公众平台已验证稳定版本 | 上传未构建或未真机验证的本地目录 |
| 云函数 | 恢复已记录版本和安全开关 | 临时开启真实 Provider/quota 验证 |
| 数据库 | 保持数据不变，必要时收紧访问 | 删除、批量改写或扩大权限 |
| AI 服务 | 关闭真实调用并保留明确失败 | 静默回退为正式成功 mock |
| 支付/交付 | 保持关闭 | 通过前端按钮隐藏代替服务端控制 |

## 回滚验收

- [ ] 旧版本可正常启动和导航。
- [ ] 无跨用户数据访问。
- [ ] 不发生真实 Provider、quota、支付或交付。
- [ ] mock/fallback 仍明确标记且不可正式交付。
- [ ] 任务和作品历史未被删除。
- [ ] 客服、隐私指引和协议入口与旧版本声明一致。
- [ ] Android/iOS 至少各完成一次关键回归（如发布负责人要求）。
