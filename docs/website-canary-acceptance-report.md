## 灰度策略

### stage_1_internal
- 范围：仅内部测试账号
- 限制：单张图片、单功能、不允许正式交付
- 扩大条件：四条核心链路内部 dry-run 通过且 P0/P1 为 0
### stage_2_invited_pro
- 范围：少量受邀专业用户
- 限制：开放项目、开放版型库、开放人工审核、限制批量任务数量
- 扩大条件：任务成功率、上传成功率、权限隔离和额度一致性稳定
### stage_3_enterprise_trial
- 范围：企业试用账号
- 限制：开放团队协作、开放小批量任务、正式交付需人工确认
- 扩大条件：连续观察周期内无 P0/P1，P2 有替代流程

## 问题分级

- P0：数据泄露、重复扣费、错误交付，立即停止灰度
- P1：核心流程无法完成，停止新增用户
- P2：部分功能异常，有替代流程
- P3：样式、文案或轻微体验问题

## 发布建议

- P0/P1 未清零前，不允许扩大灰度。
- mock、fallback 或测试结果进入审核/交付时，立即停止灰度。
- 每个问题必须记录负责人、影响范围、复现步骤、修复版本和验证结果。
- 回滚入口：按 `docs/website-production-deployment.md` 重新部署上一稳定 H5 静态产物。
