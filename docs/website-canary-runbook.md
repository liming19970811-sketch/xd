# 官网全链路验收与灰度上线 V1

## 验收原则

- 先内部小范围验证真实业务流程，再逐步开放正式用户。
- 禁止使用真实客户隐私数据。
- 每类账号使用独立测试企业、项目、任务、作品、版型和交付数据。
- 未完成真实链路前，不允许以静态页面或示例数据冒充验收通过。
- mock、fallback 和测试结果不得进入正式交付。

## 验收账号

| 账号类型 | 权限目标 | 数据要求 |
| --- | --- | --- |
| 未登录访客 | 只可访问公开官网 | 无私有数据 |
| 个人用户 | 可进入个人工作台 | 独立个人项目和作品 |
| 设计师 | 可创建 AI 出图任务 | 独立设计项目 |
| 版师 | 可修订和审核版型 | 独立制版项目 |
| 项目负责人 | 可管理项目与批次 | 独立企业项目 |
| 企业管理员 | 可管理成员、角色、项目和交付 | 独立测试企业 |
| 只读成员 | 只能查看授权数据 | 独立只读成员账号 |
| 平台管理员 | 可查看平台级运营数据 | 平台测试账号 |

## 核心验收链路

### 链路 A：AI 出图

1. 登录。
2. 创建项目。
3. 上传服装图。
4. 选择功能。
5. 确认额度。
6. 生成。
7. 审核。
8. 加入作品库。

通过标准：

- 生成任务有唯一 `taskId`。
- 任务状态与列表统计一致。
- mock/fallback 结果不可正式审核交付。
- 加入作品库后可追溯项目和原始任务。

### 链路 B：AI 制版

1. 上传服装图。
2. 结构识别。
3. 生成结构图。
4. 版师修订。
5. 提交审核。
6. 创建版本。
7. 加入版型库。

通过标准：

- AI 原稿与版师修订分开保存。
- 创建新版本，不覆盖已审核版本。
- 未审核版型不可标记为生产可用。

### 链路 C：批量交付

1. 创建批次。
2. 批量生成。
3. 重试失败项。
4. 批量审核。
5. 创建交付批次。
6. 下载交付文件。

通过标准：

- 重试只处理失败项。
- 同一幂等键不重复创建任务或扣费。
- 已交付资产不可被后续修改覆盖。
- 下载链接过期后不可继续访问。

### 链路 D：企业协作

1. 邀请成员。
2. 分配角色。
3. 加入项目。
4. 完成任务。
5. 审核。
6. 查看审计日志。

通过标准：

- 不同角色只能看到和操作授权内容。
- 禁用成员立即失去企业访问权限。
- 审核、交付、角色调整和成员操作均有审计日志。

## 异常链路

- 图片上传失败。
- AI 接口超时。
- 任务生成失败。
- 额度不足。
- 重复点击提交。
- 页面刷新。
- 登录过期。
- 无权限访问。
- 企业切换。
- 批量任务部分失败。
- 下载链接过期。
- mock 或 fallback 结果进入审核。

## 数据一致性

- 任务状态与列表统计一致。
- 扣费、回滚和剩余额度一致。
- 项目、批次、作品引用一致。
- 版型版本和审核状态一致。
- 已交付资产不会被覆盖。
- 同一幂等键不会重复创建任务或扣费。

## 灰度阶段

### 第一阶段：内部测试账号

- 单张图片。
- 单功能。
- 不允许正式交付。
- P0/P1 为 0 后进入第二阶段。

### 第二阶段：受邀专业用户

- 开放项目、版型库和人工审核。
- 限制批量任务数量。
- 指标稳定后进入第三阶段。

### 第三阶段：企业试用账号

- 开放团队协作和小批量任务。
- 正式交付必须人工确认。
- 连续观察周期内无 P0/P1 后逐步扩大。

## 监控指标

- 登录成功率。
- 上传成功率。
- 任务成功率。
- 平均生成耗时。
- 审核通过率。
- 重试率。
- 额度异常数量。
- 页面错误率。
- 用户完成第一个任务的比例。
- 不同功能入口点击率。

## 问题分级

- P0：数据泄露、重复扣费、错误交付，立即停止灰度。
- P1：核心流程无法完成，停止新增用户。
- P2：部分功能异常，有替代流程。
- P3：样式、文案或轻微体验问题。

每个问题必须记录负责人、影响范围、复现步骤、修复版本和验证结果。
