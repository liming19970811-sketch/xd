# RC1 问题分级与归因表

## 严重等级

| 等级 | 判定标准 | 示例 | RC1 动作 |
| --- | --- | --- | --- |
| P0 | 无法启动或大面积白屏；跨用户数据泄露；意外真实扣点/支付/交付；数据破坏；核心任务重复且造成真实扣点 | 启动即崩溃、A 可查看 B 作品、单次点击产生多次真实扣点 | 立即停止测试和上传，负责人确认后修复 |
| P1 | 核心主链对多数用户不可用且无绕过；任务丢失；mock 任务稳定重复创建；结果错误收录或审核红线失效 | 上传后无法生成、后台恢复丢任务、mock 结果可正式交付 | 停止 RC1，修复后完整回归 |
| P2 | 功能受影响但存在明确绕过；特定设备兼容问题；错误提示或状态恢复不完整 | 某机型相册授权需重进、草稿部分字段未恢复 | 修复或记录明确延期理由并评估风险 |
| P3 | 不影响任务完成的视觉、文案、间距或低频体验问题 | 小屏文字轻微截断、次要文案不统一 | 登记处理，不得伪装成已验证 |

没有证据时使用“待分级”，不得为了达到准入条件自行降级。安全、权限、额度和支付问题至少由发布负责人复核一次。

## 问题归因

| 分类 | 识别依据 | 处理入口 |
| --- | --- | --- |
| `code` | 多设备或稳定步骤可复现，页面逻辑、路由、状态、重复提交或数据归一异常 | 代码修复后执行相关链路回归 |
| `config` | AppID、基础库、域名、隐私声明、feature flag 或构建配置不一致 | 配置负责人核对；记录修改前后摘要 |
| `cloud_environment` | 云函数未部署、版本不一致、环境变量、数据库规则、云存储或网络服务异常 | 云开发控制台复验；不得由前端假成功兜底 |
| `device_compatibility` | 只在特定机型、系统、微信版本、字体、网络或安全区出现 | 同类设备复现并保留对照结果 |
| `unknown` | 当前证据无法区分 | 补充最小复现与安全日志后再归因 |

## 冲突判定

1. 同一问题跨设备稳定出现，优先检查 `code` 或 `cloud_environment`。
2. 只有单一体验版构建出现，先检查 `config` 和云函数版本。
3. 仅单一机型出现且相同账号在其他设备正常，可暂归 `device_compatibility`。
4. 涉及其他账号数据时，不等待完整归因，先按 P0 安全事件处理。
5. 云调用成功不代表业务成功；业务错误必须保留原状态，不得包装成网络失败或成功。

## 回归状态

| 状态 | 含义 |
| --- | --- |
| `new` | 新反馈，尚未确认 |
| `triaged` | 已复现并完成等级、归因 |
| `fixing` | 正在修复或配置调整 |
| `ready_for_retest` | 已有候选修复，尚未体验版复测 |
| `verified` | 目标体验版按原步骤复测通过 |
| `closed` | 已验证并完成相关回归 |
| `deferred` | 有负责人、理由、风险和目标版本的明确延期 |

禁止从 `fixing` 直接标记 `closed`；禁止把 `NOT RUN` 当作 PASS。
