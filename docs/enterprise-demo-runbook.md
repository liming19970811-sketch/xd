# 企业客户完整演示流程 Runbook

本文档用于记录一次完整企业客户业务闭环验收流程，覆盖从官网线索提交、销售跟进、项目创建、AI 生产、交付，到经营后台查看的演示路径。

本流程只用于演示和验收，不要求开启真实扣点、真实支付或真实 provider 开关。

## 1. 企业需求提交

目标：验证企业客户可以从官网或企业入口提交需求，并生成可追踪线索。

操作：

1. 打开官网企业需求入口。
2. 填写企业名称、联系人、联系方式、需求类型、预算范围、预计出图数量和补充说明。
3. 提交需求。
4. 确认提交逻辑复用 `submitLead` 和 `createProjectFromLead`。

验收记录：

| 字段 | 记录值 | 说明 |
| --- | --- | --- |
| `leadId` |  | 企业线索 ID |
| `projectId` |  | 由线索创建或关联的项目 ID |
| 来源 |  | 官网、案例、文章、服务方案等 |
| 需求快照 |  | 款式、平台、数量、预算等核心信息 |

通过标准：

- 已生成 `leadId`。
- 需求快照可在后台识别。
- 不改变 `taskId / batchId / projectId / assetId / deliveryId` 字段语义。

## 2. 销售跟进

目标：验证销售可以围绕企业线索创建跟进记录。

操作：

1. 进入后台客户跟进视图。
2. 找到刚提交的企业客户。
3. 新增一次跟进记录，例如“首次联系”或“需求确认”。
4. 填写跟进内容、操作人和下次跟进时间。

验收记录：

| 字段 | 记录值 | 说明 |
| --- | --- | --- |
| `followId` |  | 销售跟进记录 ID |
| `leadId` |  | 关联企业线索 |
| `projectId` |  | 关联项目 |
| actionType |  | 首次联系、需求确认、方案发送等 |
| nextFollowAt |  | 下次跟进时间 |

通过标准：

- 跟进记录关联正确的 `leadId`。
- 后台能看到最近记录和下次跟进时间。
- 不修改官网提交逻辑。

## 3. 销售漏斗

目标：验证企业客户可以进入销售阶段管理。

操作：

1. 进入后台销售漏斗视图。
2. 找到目标客户。
3. 将客户阶段从 `new_lead` 调整为后续阶段，例如 `contacted`、`requirement_confirmed`、`solution_sent` 或 `quotation`。
4. 确认阶段变化会生成跟进记录。

验收记录：

| 字段 | 记录值 | 说明 |
| --- | --- | --- |
| `pipelineId` |  | 销售漏斗记录 ID |
| `leadId` |  | 关联企业线索 |
| `stage` |  | 当前销售阶段 |
| `probability` |  | 当前成交概率 |
| `amount` |  | 预计金额 |

通过标准：

- 销售阶段可流转。
- `pipeline` 阶段和概率匹配。
- 阶段变化记录可在客户跟进中查看。

## 4. 销售预测

目标：验证系统可以基于销售阶段生成预测。

操作：

1. 进入后台销售预测视图。
2. 查看目标客户的预计成交金额、客户阶段、成交概率、预计日期和风险等级。
3. 对照销售漏斗阶段确认概率计算合理。

验收记录：

| 字段 | 记录值 | 说明 |
| --- | --- | --- |
| `forecastId` |  | 销售预测 ID |
| `leadId` |  | 关联企业线索 |
| `projectId` |  | 关联项目 |
| stage |  | 销售阶段 |
| probability |  | 成交概率 |
| expectedAmount |  | 预计成交金额 |
| riskLevel |  | 风险等级 |

通过标准：

- 销售预测能识别目标客户。
- 成交概率随销售阶段变化。
- 长时间未更新客户会显示风险。

## 5. 企业项目创建

目标：验证企业线索可以沉淀为企业项目。

操作：

1. 在后台客户或项目视图确认目标项目。
2. 查看项目名称、客户名称、项目状态和需求信息。
3. 如有项目状态操作，记录当前状态，不做超出演示范围的业务变更。

验收记录：

| 字段 | 记录值 | 说明 |
| --- | --- | --- |
| `projectId` |  | 企业项目 ID |
| `leadId` |  | 来源线索 ID |
| projectName |  | 项目名称 |
| status |  | 当前项目状态 |
| deadline |  | 计划截止时间 |

通过标准：

- 项目能关联到原始企业线索。
- 后台项目视图可识别项目状态。
- 不改变项目 ID 语义。

## 6. 品牌工作空间

目标：验证企业客户可以沉淀品牌资产空间。

操作：

1. 进入品牌或企业 API 相关后台区域。
2. 查看或创建演示品牌工作空间。
3. 记录品牌名称、品牌颜色、品牌模特、品牌场景、品牌模板等资产信息。

验收记录：

| 字段 | 记录值 | 说明 |
| --- | --- | --- |
| `brandId` |  | 品牌空间 ID |
| brandName |  | 品牌名称 |
| brandColors |  | 品牌颜色 |
| brandModels |  | 品牌模特 |
| brandScenes |  | 品牌场景 |

通过标准：

- 品牌空间能表达企业客户的视觉资产。
- 品牌资产不影响生成链路和 provider 开关。

## 7. 工作台项目空间

目标：验证工作台可以承接企业项目上下文。

操作：

1. 进入 AI 出图工作台。
2. 选择演示能力，例如换模特、换颜色、换场景、微改款或电商主图。
3. 确认当前操作上下文可以记录项目、来源和参数信息。

验收记录：

| 字段 | 记录值 | 说明 |
| --- | --- | --- |
| `workspaceContext` |  | 工作台上下文 |
| `projectId` |  | 关联企业项目 |
| type |  | 当前出图能力 |
| params |  | 比例、风格、颜色、场景等参数 |

通过标准：

- 工作台上下文可说明本次生成属于哪个项目。
- 参数可以形成后续 task 输入。
- 不破坏现有上传到结果链路。

## 8. AI 生产

目标：验证 AI 生产可以形成任务和资产。

操作：

1. 在工作台或上传页上传参考图。
2. 选择参数并点击生成。
3. 确认系统创建任务。
4. 进入结果页查看生成结果或 mock fallback 结果。

验收记录：

| 字段 | 记录值 | 说明 |
| --- | --- | --- |
| `taskId` |  | AI 生产任务 ID |
| `assetId` |  | 生成资产 ID |
| type |  | 生成类型 |
| status |  | pending、processing、success 或 failed |
| resultImageUrl |  | 结果图片地址 |

通过标准：

- 生成任务有 `taskId`。
- 结果资产可被结果页或作品列表读取。
- 不开启真实扣点或支付逻辑。

## 9. 交付流程

目标：验证企业项目可以形成交付记录。

操作：

1. 在项目或交付后台中查看生成资产。
2. 创建或查看交付记录。
3. 确认交付状态，例如待审核、已确认、已交付。
4. 如存在审核拦截，确认 mock / fallback 结果不会被错误标记为正式交付。

验收记录：

| 字段 | 记录值 | 说明 |
| --- | --- | --- |
| `deliveryId` |  | 交付记录 ID |
| `projectId` |  | 关联项目 |
| `assetId` |  | 关联资产 |
| status |  | 交付状态 |
| reviewedAt |  | 审核时间 |

通过标准：

- 交付记录可关联项目和资产。
- 交付状态可在后台查看。
- 不破坏结果页审核拦截逻辑。

## 10. 经营后台查看

目标：验证经营后台可以查看完整经营结果和下一步动作。

操作：

1. 进入经营驾驶舱，查看新增客户、销售阶段金额、预计成交金额、项目数量、交付数量和 API 使用情况。
2. 进入经营预警，查看销售、项目、交付、API 风险。
3. 进入经营报告，查看周期复盘。
4. 进入经营洞察，查看经营总结、重点机会、风险提醒、行动建议。
5. 进入经营助手，查看今日建议、重点客户、重点项目、风险处理建议。

验收记录：

| 模块 | 记录值 | 说明 |
| --- | --- | --- |
| `dashboard` |  | 经营驾驶舱周期数据 |
| `report` |  | 经营复盘报告 |
| `insight` |  | 经营洞察 |
| `advisor` |  | 经营助手建议 |

通过标准：

- 后台可以从线索、销售、项目、交付和 API 数据形成经营视图。
- `dashboard / report / insight / advisor` 都能展示企业经营闭环状态。
- 所有经营模块只读聚合，不修改原始业务数据。

- 不修改生成链路。
- 不修改 quota / provider。
- 不修改支付。
- 不修改官网。
- 不修改 `pages.json`。
